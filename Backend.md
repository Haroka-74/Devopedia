# Delegates vs. Events: Understanding the Difference

```csharp
// The referee should be the only one who can raise the goal announcement.
public class Referee
{
    public Action? GoalScored;

    public void ScoreGoal()
    {
        Console.WriteLine("Referee: Goal has been scored!");
        GoalScored?.Invoke();
    }
}

public class Program
{
    static void Main()
    {
        var referee = new Referee()
        {
            // Anyone can rest the delegate directly.
            GoalScored = null
        };

        referee.GoalScored += () => Console.WriteLine("Player A celebrates!");
        referee.GoalScored += () => Console.WriteLine("Player B is crying!");

        // Any player (or any code) can call the delegate directly.
        // referee.GoalScored();

        referee.ScoreGoal();
    }
}
```
```csharp
public class Referee
{
    // An Event declaration adds a layer of abstraction and protection on the delegate instance.
    public event Action? GoalScored;

    public void ScoreGoal()
    {
        Console.WriteLine("Referee: Goal has been scored!");
        GoalScored?.Invoke();
    }
}

public class Player(string name)
{
    public void React() => Console.WriteLine($"{name} reacts to the goal!");
}

public class Program
{
    static void Main()
    {
        var referee = new Referee();

        var p1 = new Player("Player A");
        var p2 = new Player("Player B");

        referee.GoalScored += p1.React;
        referee.GoalScored += p2.React;

        // Only the referee decides when goal happens.
        referee.ScoreGoal();
    }
}
```

# Managed Code vs. Unmanaged Code

- **<ins>Managed Code</ins>** **⟶** This is code that runs under the control of the .NET Common Language Runtime (CLR). When you write normal C# code, you're writing managed code.
    - The CLR handles memory management automatically through garbage collection, provides type safety, security checks, and exception handling.
    - Gets compiled to Intermediate Language (IL), then Just-In-Time compiled to native code, with the runtime managing the entire execution lifecycle.
- **<ins>Unmanaged Code</ins>** **⟶** This is code that executes directly on the operating system, outside the CLR's control. Examples include code written in **C/C++**, or when you use platform APIs directly.
    - You must manually manage memory allocation and deallocation, with no automatic garbage collection.
    - Runs as native machine code with direct access to system resources and memory.

# Dispose Pattern

```csharp
class CoinbaseService : IDisposable
{
    private readonly HttpClient _httpClient;
    private bool _disposed = false;

    public CoinbaseService()
    {
        _httpClient = new HttpClient();
    }

    public async Task<string> GetCurrenciesAsync()
    {
        if (_disposed)
            throw new ObjectDisposedException(nameof(CoinbaseService));

        var response = await _httpClient.GetAsync("https://www.coinbase.com/api/v2/currencies");

        response.EnsureSuccessStatusCode();

        return await response.Content.ReadAsStringAsync();
    }

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);
    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed)
            return;

        if (disposing)
        {
            _httpClient?.Dispose();
        }

        _disposed = true;
    }
}
```
```csharp
class Program
{
    static async Task Main()
    {
        using (var service = new CoinbaseService())
        {
            string result = await service.GetCurrenciesAsync();
            Console.WriteLine(result);
        }
    }
}
```

```csharp
static void ListDirectory(string path)
{
    try
    {
        if (!Directory.Exists(path))
        {
            Console.WriteLine("Directory does not exist");
            return;
        }

        var table = new Table().AddColumn("Name").AddColumn("Size (KB)").AddColumn("Type");

        foreach (var directory in Directory.GetDirectories(path))
        {
            string name = Path.GetFileName(directory);

            if (name.Length > 27)
                name = string.Concat(name.AsSpan(0, 27), "...");

            table.AddRow(name, "<DIR>", "Folder");
        }

            string name = Path.GetFileNameWithoutExtension(file);

            double sizeKB = fileInfo.Length / 1024.0;
            string size = sizeKB < 0.01 ? "< 0.01" : sizeKB.ToString("0.##");
            string extension = fileInfo.Extension.TrimStart('.');

            table.AddRow(name, size, extension);
        }

        AnsiConsole.Write(table);
```

- This method reads the file header (magic bytes) to identify the image format without loading the entire file:
```csharp
DetectImageType(@"C:\Users\hp\Desktop\image.jpg");

static void DetectImageType(string path)
{
    try
    {
        if (!File.Exists(path))
        {
            Console.WriteLine("Image file does not exist");
            return;
        }

        using var fileStream = new FileStream(path, FileMode.Open, FileAccess.Read);

        byte[] header = new byte[8];
        int bytesRead = fileStream.Read(header, 0, header.Length);

        if (bytesRead < 4)
        {
            Console.WriteLine("File is too small to determine type");
            return;
        }

        // https://en.wikipedia.org/wiki/List_of_file_signatures
        if (header[0] == 0x89 && header[1] == 0x50 && header[2] == 0x4E && header[3] == 0x47)
            Console.WriteLine("Image Type: PNG (Portable Network Graphics)");
        else if (header[0] == 0xFF && header[1] == 0xD8 && header[2] == 0xFF)
            Console.WriteLine("Image Type: JPEG (Joint Photographic Experts Group)");
        else if (header[0] == 0x47 && header[1] == 0x49 && header[2] == 0x46)
            Console.WriteLine("Image Type: GIF (Graphics Interchange Format)");
        else if (header[0] == 0x42 && header[1] == 0x4D)
            Console.WriteLine("Image Type: BMP (Bitmap)");
        else
            Console.WriteLine("Unknown or unsupported image format");
    }
    catch (Exception e)
    {
        Console.WriteLine($"Exception: {e.Message}");
    }
}
```

# Concurrency in C#

- Execute two timers sequentially on the main thread - the second timer starts only after the first completes:
```csharp
Console.WriteLine("Main started");

Run("Timer 01");
Run("Timer 02");

Console.WriteLine("Main ended");

static void Run(string name)
{
    for (int i = 1; i <= 5; i++)
    {
        Console.WriteLine($"{name}: {i}s, thread: {Environment.CurrentManagedThreadId}");
        Thread.Sleep(1000);
    }

    Console.WriteLine($"{name} completed");
}
```
- Create two foreground threads that execute concurrently - the main thread exits immediately without waiting for workers to finish:
```csharp
Console.WriteLine("Main started");

Thread t1 = new(() => Run("Timer 01")) { Name = "01" };
Thread t2 = new(() => Run("Timer 02")) { Name = "02" };

t1.Start();
t2.Start();

Console.WriteLine("Main ended");

static void Run(string name)
{
    for (int i = 1; i <= 5; i++)
    {
        Console.WriteLine($"{name}: {i}s, thread: {Environment.CurrentManagedThreadId}");
        Thread.Sleep(1000);
    }

    Console.WriteLine($"{name} completed");
}
```
- Use `Join()` to block the main thread until all worker threads complete, ensuring proper synchronization before termination:
```csharp
Console.WriteLine("Main started");

Thread t1 = new(() => Run("Timer 01")) { Name = "01" };
Thread t2 = new(() => Run("Timer 02")) { Name = "02" };

t1.Start();
t2.Start();

t1.Join();
t2.Join();

Console.WriteLine("Main ended");

static void Run(string name)
{
    for (int i = 1; i <= 5; i++)
    {
        Console.WriteLine($"{name}: {i}s, thread: {Environment.CurrentManagedThreadId}");
```

# HTTP/1 vs. HTTP/2

- Configure `tcpdump` to capture only `SYN` packets and observe TCP connection establishment:
```bash
tcpdump -i any 'tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0'
```
> This filter shows each new TCP connection as it's created, helping you understand connection behavior across HTTP versions.
- `HTTP/1.0` creates a new TCP connection for every request, regardless of whether requests are sequential or parallel:
```csharp
// Sequential Requests (5 connections)
using var client = new HttpClient();

client.DefaultRequestVersion = new Version(1, 0);

for (int i = 1; i <= 5; i++)
{
    await client.GetAsync("https://dummyjson.com/products");
    Console.WriteLine($"Request {i}/5 completed");
}
```
```csharp
// Parallel Requests (2 connections)
using var client = new HttpClient();

client.DefaultRequestVersion = new Version(1, 0);

var t1 = new Thread(() =>
{
    _ = client.GetAsync("https://dummyjson.com/products").Result;
    Console.WriteLine("Request 1 completed");
});

var t2 = new Thread(() =>
{
    _ = client.GetAsync("https://dummyjson.com/products").Result;
    Console.WriteLine("Request 2 completed");
});

t1.Start();
t2.Start();

t1.Join();
t2.Join();
```
- `HTTP/1.1` introduces connection keep-alive, reusing TCP connections for sequential requests. However, parallel requests still require separate connections due to head-of-line (HoL) blocking at the HTTP layer:
```csharp
// Sequential Requests (1 connection)
```

- `HTTP/2` uses stream multiplexing over a single TCP connection, handling both sequential and parallel requests efficiently:
```csharp
// Sequential Requests (1 connection)
using var client = new HttpClient();

client.DefaultRequestVersion = new Version(2, 0);

for (int i = 1; i <= 5; i++)
{
    await client.GetAsync("https://dummyjson.com/products");
    Console.WriteLine($"Request {i}/5 completed");
```

```csharp
// Parallel Requests (1 connection)

{
    _ = client.GetAsync("https://dummyjson.com/products").Result;
    Console.WriteLine("Request 1 completed");

{

    Console.WriteLine("Request 2 completed");
```

> However, `HTTP/2` still suffers from TCP-level head-of-line blocking: when a TCP packet is lost, all `HTTP/2` streams over that connection must wait for retransmission, even if the data for some streams has already arrived. This means that while `HTTP/2` improves concurrency at the application layer, it cannot fully eliminate delays caused by packet loss at the transport layer.

inversion of Control 'IoC': is a principal design that allows classes to be loosely coupled and therefore, easier to test and maintain [ not creation of class inside another class ].
    - IoC: refers to transferring the control of objects and their dependencies from the main program to a container or framework.
    - IoC: is a principal, not a design Pattern.
    ---- benefits:
        - reduce the code amount.
        - decrease coupling between classes.
        - make the application easier to test and maintain.

- IoC Patterns:
    - Service Locater
    - Factory
    - Template method
    - abstract Factory
    - Strategy
    - Dependency Injection: in our model

steps:
======
tightly coupled classes ===> implement IoC using Factory Pattern 'built-in class' ===> implement DIP 'Dependency Inversion Principle' by creating abstractions ===> implement DI 'dependency injection' ===> use IoC container 'remove any new keyword' ===>

injection types:
    - constructor [ .NET core default ]
    - property
    - method parameter

- Controller Factory: is responsible for create an object from the parameter in injection by asking thing called 'IoC Container'.
